# HTML Runner — iOS app + Share Extension

An iPhone app that **reads HTML you share from other apps**. Safari, Mail, Messages, Files,
Notes, an AI chat, a code editor — tap **Share**, pick **HTML Runner**, and the page or snippet
opens immediately in a native reader, then stays in your library.

Built as a real Xcode project: a SwiftUI app + a `share-services` app extension.

## How it works

```
 other app (Safari, Mail, Messages, Files…)
        │  Share → HTML Runner
        ▼
 ShareExtension: ShareViewController
        │  grabs HTML / web page / data: URL / file / text
        │  writes SharedHTMLItem JSON into an App Group container
        │  opens htmlrunner://open?id=<uuid>
        ▼
 App: LibraryStore reads the shared container → ViewerScreen
        │
        ▼
 WKWebView renders it (full documents as-is, fragments/plain text auto-wrapped)
```

## Requirements

* A Mac with **Xcode 15 or later**
* An **iPhone running iOS 17+** (the Simulator works too, but share sheets behave better on a real device)
* An Apple ID — a **free** account is fine (Personal Team). Apps made this way stop working after 7 days
  unless you re-Run from Xcode, so a paid Apple Developer account is worth it if you want it to stick around.

## Setup — about 5 minutes

1. **Unzip** and open `HTMLRunner.xcodeproj` in Xcode.

2. **Signing — target 1.** Select the blue project → target **HTMLRunner** → *Signing & Capabilities*:
   * Tick **Automatically manage signing**
   * **Team:** your Apple ID
   * **Bundle Identifier:** change `com.example.htmlrunner` to something unique, e.g. `com.yourname.htmlrunner`

3. **Signing — target 2.** Same steps for the **Open in HTML Runner** target:
   * Bundle Identifier: `com.yourname.htmlrunner.share` (must be the app ID + `.share`)

4. **App Groups** (how the extension hands HTML to the app). Still in *Signing & Capabilities*, for
   **both** targets: **+ Capability → App Groups → +** and add:

   ```
   group.com.yourname.htmlrunner
   ```

   Then tell the code about your group — two edits, same string:
   * `Shared/SharedStore.swift` → `static let appGroupID = "group.…"` (currently `group.com.example.htmlrunner`)
   * `HTMLRunner/HTMLRunner.entitlements` and `ShareExtension/ShareExtension.entitlements` → the `<string>` inside `com.apple.security.application-groups`

5. **Run.** Connect your iPhone, choose it as the destination, press ⌘R.

6. **Trust the app on the phone** (first install only): on the iPhone → *Settings → General →
   VPN & Device Management → Developer App → your Apple ID → Trust*. On iOS 16+ also enable
   *Settings → Privacy & Security → Developer Mode*, then restart the phone.

7. **Enable it in the share sheet** (once): in any app tap Share, scroll the app row, tap
   **More / ⋯ → Edit**, switch **HTML Runner** on, and drag it up the list.

## Using it

**Safari** — tap Share → **HTML Runner**. For the *page* rather than the link, choose
**Options → Web Page** in the share sheet; either works (a link is fetched and cached by the
extension, a web page arrives as HTML directly).

**Messages / Mail / Notes / an AI chat** — share a snippet; it is stored and rendered as
pre-formatted text (or as HTML if it contains tags).

**Files** — share an `.html`/`.htm` file; it renders with its sibling files as the base URL,
so local images and CSS next to it load.

Inside the app:

* **Home** — recent items as cards; **+** to paste HTML yourself
* **Library** — everything, with search; swipe to delete
* **Viewer** — reload, open in Safari, **View source**, copy HTML/URL, share onward
* **Settings** — extension status, how to enable it, library size, how to clear everything

## What the extension accepts

| Shared as | Result |
|---|---|
| Web page (`public.html`) | Rendered from local HTML, base URL set when available |
| Link (`public.url`) | Fetched and cached by the extension; falls back to loading the URL live |
| `data:text/html,…` / `data:text/html;base64,…` | Decoded and rendered |
| File (`.html`, `.htm`, anything text) | Rendered, with the file's folder as base URL |
| Plain text | Wrapped in `<pre>` — tags are rendered if the text contains any |

## Getting an .ipa (install on your iPhone)

An `.ipa` is a compiled, code-signed iOS binary — it can only be produced by Xcode on macOS
(this project was written on Linux, so there is no prebuilt `.ipa` in the zip). You have three
practical routes, one of which needs no Mac at all:

| Route | You need | You get |
|---|---|---|
| **1. Cloud build** (below) | a free GitHub account | unsigned `.ipa` → re-sign with Sideloadly / AltStore |
| **2. Local build** | a Mac + Xcode | signed `.ipa` in one command |
| **3. TestFlight** | paid Apple Developer account | signed `.ipa` + OTA install via TestFlight |

### Route 1 — build in the cloud (no Mac)

> Uploading is its own walkthrough: see **[UPLOAD-GUIDE.md](UPLOAD-GUIDE.md)** (three ways, click by click).


1. Push this folder to a GitHub repo (private is fine).
   `.github/workflows/build-ipa.yml` is already included.
2. GitHub → **Actions → Build IPA → Run workflow** (it also runs on every push).
3. When the run goes green, open it → **Artifacts → HTMLRunner-unsigned-ipa** → download and unzip
   → `HTMLRunner-unsigned.ipa`. The workflow also verifies the share extension is embedded.
4. Install with **[Sideloadly](https://sideloadly.io)** (Windows or Mac) or **AltStore**: connect the
   iPhone, drag the `.ipa` in, and sign in with your Apple ID. A free Apple ID signs for 7 days
   (just re-sideload), a paid one for a year.
5. On the iPhone: *Settings → General → VPN & Device Management → your Apple ID → Trust*.

> An unsigned `.ipa` **cannot** be installed directly on a stock iPhone — it must be re-signed
> (Sideloadly/AltStore do this for you) or installed on a jailbroken device.
>
> Re-signing with a personal Apple ID strips the **App Group** entitlement, so the extension can't
> use the shared container. HTML Runner detects this automatically and hands shared items to the
> app **inside the `htmlrunner://` link** instead — sharing keeps working for snippets and small
> pages (up to ~75 KB of HTML). *Settings* inside the app tells you which mode is active.

### Route 2 — build on a Mac in one command

```bash
./tools/make_ipa.sh --team ABCDE12345 --bundle com.yourname.htmlrunner
# → build/ipa/HTMLRunner.ipa
```

The script rewrites the bundle identifier, the extension's identifier (`…​.share`), the App Group
and `SharedStore.appGroupID` for you, then archives and exports. Useful flags:

```bash
--method development        # install on a device connected to your Mac (default)
--method ad-hoc             # install on registered devices by sharing the IPA
--method app-store-connect  # TestFlight / App Store
```

Install a `development`/`ad-hoc` build by dragging the `.ipa` onto **Xcode → Window → Devices and
Simulators**, or with **Apple Configurator**.

### Route 3 — TestFlight via the workflow

With a paid Apple Developer account, the second job in the workflow builds a properly signed
`.ipa` automatically. Add these repository secrets (App Store Connect → Users and Access →
Integrations → App Store Connect API keys):

```
ASC_KEY_ID      the key's ID
ASC_ISSUER_ID   the issuer ID
ASC_KEY_P8      the whole AuthKey_XXXX.p8 file, base64-encoded (base64 -i AuthKey_XXXX.p8)
TEAM_ID         your 10-character Team ID
```

Then run the workflow with `export_method = app-store-connect` and `upload_to_testflight = true`.
The API key lets `xcodebuild` create and fetch the provisioning profiles for both the app and its
extension by itself — no certificates to manage.

Other Mac-in-the-cloud options that work the same way: Xcode Cloud (built into App Store Connect),
Codemagic, Bitrise.

## Troubleshooting

| Symptom | Fix |
|---|---|
| No “HTML Runner” in the share sheet | Share sheet → **More / Edit** → enable it. It hides when the shared item type isn't in the activation rule. |
| Share sheet appears, but the app shows nothing after tapping **Open** | App Groups not configured for *both* targets, or the group string differs between `SharedStore.swift` and the entitlements. **Settings** inside the app shows the status. |
| Build error: *“…isn't available on iOS (App Extension)”* | Something app-only leaked into the extension. The project is clean as shipped; keep the extension target's membership limited to `ShareViewController.swift`, `SharedHTMLItem.swift`, `SharedStore.swift`. |
| Build error about entitlements / provisioning | The App Group isn't in your provisioning profile yet: re-check step 4, then in Xcode *Product → Clean Build Folder* and Run again. |
| The app stopped working after a week | Free Apple ID signing expires; Run from Xcode again (or use a paid account). |
| Sideloaded build: share sheet → HTML Runner does nothing | The app was re-signed without entitlements and the payload was too big for the link. Small snippets work; for big pages build with a paid account (Route 3) so App Groups survive. |
| Sideloadly errors “unable to install” | The `.ipa` was unsigned: use the workflow artifact (unsigned → Sideloadly re-signs it) rather than trying to install it directly. |
| Page renders blank / unstyled | It likely relies on a remote stylesheet that needs the network, or on JS the page loads from a CDN. Use **View source** to confirm what arrived. |

## Security notes

* Remote pages are loaded with their **real origin** — exactly like Safari, keeping their normal
  web security model.
* Local HTML coming from a share is loaded with its page/file base URL (so relative assets work).
  If you want local documents fully sealed off, pass `nil` instead of `item.baseURL` in
  `Renderer.swift`.
* JavaScript is enabled (`allowsContentJavaScript`) because most shared snippets are JS-driven.
  Disable it there too if you prefer a text-only reader.
* Nothing is uploaded anywhere: the library is a JSON file in the App Group container on your phone.

## Rebuilding the Xcode project file

`project.pbxproj` is generated, so it can be regenerated after adding files:

```bash
python3 tools/make_pbxproj.py      # writes HTMLRunner.xcodeproj/project.pbxproj
python3 tools/validate_project.py  # parses it back and checks targets/membership/plists
python3 tools/check_symbols.py     # catches "cannot find 'X' in scope" before CI does
```

Add a file to `FILES` (and to `APP_SOURCES` / `EXT_SOURCES`) in `tools/make_pbxproj.py` and re-run both.
`validate_project.py` needs `pip install pbxproj` on macOS.
